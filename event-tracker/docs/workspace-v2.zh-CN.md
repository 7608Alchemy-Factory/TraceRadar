ExampleSoft 是虚构公司。原 `main` 分支 `f472965` 就有三批模拟新闻、MockProvider 规则、状态管理、通知和初版前端。
原始输入在 `fixtures/cybersecurity/1.json`、`2.json`、`3.json`。本次没有改写这些文件。

上轮“D验收”是开发时创建的测试 Topic，不是产品功能；另加的一条 editorial clarification 是开发验收用的模拟补充信息。

| 原始输入 | 系统行为 | 证明什么 |
|---|---|---|
| 第一批：披露 A；另有体育新闻 | 新建事件 A；排除体育新闻 | 一篇新闻不一定成为事件；先判断相关性 |
| 第二批：A 受影响版本、同文转载、独立漏洞 B | 更新 A；转载去重；新建 B | 同一事项延续，独立事项分开 |
| 第三批：A 补丁、版本冲突、模糊线索 | A 变为 patched；产生提醒；冲突与线索进入审核 | 状态变化可通知；不确定信息不自动覆盖事实 |
| 重复运行相同批次 | 不重复增加状态变化或通知 | 去重与幂等 |

这些是预先写好的规则演示，能检查工程流程，不能证明大模型已经理解新闻。

## 二、现在怎样看页面

日常启动：双击仓库根目录 `Start-TraceRadar.cmd`；停止：双击 `Stop-TraceRadar.cmd`。
启动窗口关闭后，后台进程继续运行；重启 Windows 后需再次启动。
此模式用同一个进程在 5173 端口提供界面和 API，不再依赖聊天里的临时终端。
API 文档为 `http://127.0.0.1:5173/docs`，日志在 `event-tracker/data/local-workspace.log`。
原有数据库与模型配置继续使用。修改前端源码后，需要先重新构建前端。

打开 `http://127.0.0.1:5173`。当前界面采用暗色导航、纸张色内容区、衬线标题、分隔列表与克制的绿色/赭色标记。
没有新增外部字体、图片或 UI 组件依赖。界面改变了布局与操作组织，不只是换颜色。

- 概览：当前主题、事件列表、三步演示、最近提醒、右侧检查控制。
- 事件：打开档案，查看当前事实、时间线、修改历史；点击事实旁数字查看对应证据。
- 证据库：所有已读输入，包括排除、重复、冲突和失败项。
- 待审核：比较证据，决定保留原状态或采纳后修正；右侧保留人工处理记录。
- 信息源：勾选并保存批准来源，添加手动新闻/RSS/离线回放，设置提醒偏好。
- 运行记录：检查每次处理的步骤与错误；人工修正也有独立记录，标为“人工审核”。

左下角“看懂这个演示”包含三批新闻的解释，并可创建一个干净的新演示。原有主题和记录保留。

## 三、先亲手走一遍模拟流程

1. 左下角点击“看懂这个演示”→“新建一个干净的三步演示”。
2. 在“跟着演示走一遍”中点击“发现事件”的“运行这一步”，等待完成，打开事件 A。
3. 运行“补充与归类”，观察 A 增加版本事实、B 单独出现；在证据库查到转载与排除项。
4. 运行“修复与冲突”，观察 A 变成“已修复”，即时提醒增加，并出现两条待审信息。
5. 再运行同一批次，观察事实、状态历史与提醒没有重复增长。
6. 点击事件档案中的证据数字，确认能追溯到原文、发布时间和模型/规则判断。

三批原始演示预期：2 个事件、4 次状态变化、3 条汇总提醒、1 条即时提醒、2 条待审核。手动投喂或人工采纳之后数量会增加，所以要比较原始结果请新建干净演示。

## 四、人工审核：现在已可以修正事实

在“待审核”中展开一条冲突：

1. 保留原状态：填写处理依据，点击“保留原状态并关闭”。不会修改事件或增加通知。
2. 采纳并修正：点击“采纳并修正”，选择已有事件，填写采纳后的事实和当前状态。
3. 若旧事实被新证据推翻，勾选“需要替换的旧事实”；若只是补充，则不勾选。
4. 填写处理依据，确认已核对证据，再点击“采纳并更新事件”。
5. 打开事件档案检查新事实及状态历史：旧事实仍在修改前快照中。运行记录显示“人工审核”，没有假装调用模型。

状态、历史、通知、审核记录和人工运行记录在一个事务内提交；版本冲突、写入失败不会留下半套结果。重复相同请求也不会重复更新。

人工采纳是人的判断，不代表系统自动证明报道为真。模拟演示中测试这一操作时，应在处理依据注明“仅用于模拟验收”。当前采纳需关联已有事件；还不提供人工新建事件。

## 五、以后在哪里配置真实模型

已使用本机配置的 DeepSeek 服务开展联调。无需在聊天中发送 Key，其他组员需要配置自己的凭据。

### 界面配置（推荐）

1. 打开工作台左下角“模型配置”，也可以点击右上角设置图标。
2. 在你们选定的模型服务控制台创建 API Key，确认该账号可调用哪个模型。
3. 从该服务的接口文档复制兼容 API 基础地址，填写“API 基础地址”。程序会自行追加 `/chat/completions`，不要把完整调用路径填进去。
4. 点击“读取可用模型”，选择实际 ID。这里需要 API 模型名，不是服务品牌名；例如本次 `Deepseek` 被服务端拒绝，改用实际返回的 `deepseek-flash` 后才能调用。
5. Key 填入“API Key”，点击“保存配置”。配置立即对后续运行生效，不需要重启。
6. 点击“测试连接 · 一次模型请求”：只发一次真实请求，校验返回格式，不修改事件。配置保存成功与连接成功是两回事。
7. 右侧“分析方式”选择“真实模型分析”，再运行新闻。

“API 地址、模型名、Key”三个值必须来自同一个可兼容的服务配置，不能把不同服务的值混用。服务尚未确定时，页面会明确显示未配置，不会偷偷退回 Mock。

### 实际保存位置

后端把配置保存在 `event-tracker/.env`。模型、搜索和网页抓取的 API Key 使用 AES-256-GCM 加密。Windows 使用当前账号的 DPAPI 保护加密密钥。升级后第一次启动会加密文件里已有的明文密钥，旧版 Windows 保存的密钥也可以继续读取。更换 Windows 账号或电脑时，请在界面重新输入密钥。其他系统可直接从后端进程环境提供 API Key，或通过进程环境中的 `TRACERADAR_SECRETS_KEY` 启用加密保存与迁移。

代码里的 provider 标识仍为 qwen，但实际使用哪个模型取决于这个配置。不同服务是否完全兼容仍需连接测试和真实新闻验证。
若选择直接手工编辑 `.env`，需要重启后端；通过界面保存则不用。重新打开配置窗口不会回显 Key；留空表示保留已有 Key。
配置不会写入前端代码、浏览器持久存储、事件或 Trace；`.env` 及临时配置文件已加入 Git 忽略。

## 六、准备 LBJ / NBA 的三阶段回放

1. 左侧点击“准备语料回放”。选择 LBJ 30 条，或 NBA 多事件 18 条，填写追踪目标。
2. 点击“准备回放工作区”，系统新建独立 Topic，并只批准对应离线来源。这一步不调用模型。
3. 右侧显示三个时间切片，来自这批语料的发布时间分布，不是预期答案。先选阶段 1。
4. 配置并测试真实模型后，点击“开始检查”。等运行完成，依次查看事件、证据、审核、运行记录。
5. 进入阶段 2、阶段 3，检查同一事件是否持续关联，独立事件是否分开，传闻是否被误当作确认。
6. 重复同一阶段，检查是否产生重复事实或提醒。模型配置错误会立即停止剩余批次，不会向每一条新闻重复发送错误请求。

截止时间以本地时间输入并转换为 UTC。连接器只向运行管线提供截止前的输入。阶段切换不会读取 Ground Truth。体育语料不能用 ExampleSoft 规则来验收语义效果。

回放现在只使用右侧选定语料对应的已批准来源；不会把 ExampleSoft 模拟来源、实时 RSS 和重复语料一起送入本次回放。新闻真实性和人工标签仍需 C/A 核验。真实调用结果见交付总结；工程运行成功不等于语义准确率已验证。

## 七、准备交给 A 的标注材料

在 backend 目录运行（不调用模型）：

```powershell
.\.venv\Scripts\python.exe ..\scripts\export_pilot.py --api http://127.0.0.1:5173 --topic-id 你的TopicID --output ..\evaluation\pilot\case-001
```

TopicID 可在 API 文档 `http://127.0.0.1:5173/docs` 的 GET /api/topics 中查看，或从对应运行记录的完整数据中获取。若使用双终端开发模式，API 端口仍为 8000。

输出分开保存：

- `agent-output.json`：实际事件、历史、通知、全部已读证据、最近最多 30 个 Run 的有序 Trace。
- `annotations.jsonl`：只有新闻输入和空白人工标签。需要人填写相关性、事件归属、更新类型、通知动作、支持证据和说明。
- `README.md`：标注说明。

已有标注文件不会被覆盖；数据集变化时换一个导出目录。空白是“尚未标注”，不是“不相关”。Runtime 不会读取导出的标注，也不会把真实答案写回 Prompt。没有人工标签时，不输出虚构准确率。
