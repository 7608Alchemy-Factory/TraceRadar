# Benchmark 评测发现（2026-11-20）

## 本地 Qwen 试跑结果

使用本机 Ollama `qwen3:4b`（模型 ID `359d7dd4bcda`）回放三个现有案例。运行器为 [run_benchmark.py](../scripts/run_benchmark.py)；每个案例使用独立数据库和 Replay Source，按照 `case.json` 的阶段时间读取冻结证据。模型请求采用 `assessment-v4` 提示、`reasoning_effort=none`、`temperature=0`、`seed=0`，单次请求超时 180 秒，最多尝试两次；预筛选关闭，近重复检测开启。为连接本机 Ollama，本地回环地址允许 HTTP，且请求不经过系统代理。未调用远端模型。

三个 Ground Truth 均为 `draft`，脚本标记 `evaluation_valid=false`。下面是单次试跑的开发反馈，不能计算正式准确率。原始报告保存在本地，未加入 Git：[CedarDesk](reports/benchmark-local/cedar_patch_v1-437a76c4/report.json)、[香港麦当劳](reports/benchmark-local/mcd_hk_campaigns_v1-e0adbc29/report.json)、[CVE-2024-3400](reports/benchmark-local/cve_2024_3400_v1-2f95c5af/report.json)。

### CedarDesk 虚构漏洞

三个阶段的 Run 均为 `failed`，最终没有 Event 或通知。CP-01 和 CP-02 的最终错误是 `PROVIDER_SCHEMA`：模型表示需要更新，但解析后的 `proposed_state`、`update_kind` 至少有一个为空。两者在 Assessment schema 中都允许为 `null`，也有默认值 `None`；报告未保存原始模型回复，因此无法区分字段未输出、显式输出 `null`，或究竟是哪一个字段为空。CP-03 为 `PROVIDER_UNAVAILABLE`，属于模型服务请求失败。第一阶段摄取的这三条证据一直未成功处理，后续六条证据没有进入判断。因此本次不能据此评价漏洞进展的识别效果。

### 香港麦当劳活动

首阶段 Run 为 `completed`，其余三个阶段为 `completed_with_errors`；最终有一个 Event、一条通知。MCD-01 成功提交，但 Event 标题为英文的 “HK McDonald's App Launch”、状态为 `new`，与活动追踪目标的贴合程度需要人工核对。

MCD-02 的最终错误是 `PROVIDER_SCHEMA`：模型返回的 `evidence_id` 与当前输入不一致，与 CedarDesk 的条件性字段为空不同。MCD-04 为 `PROVIDER_UNAVAILABLE`，是模型服务请求失败。MCD-03 排在 MCD-04 之后，因前序错误中断该批处理而未进入判断；其“同一篇文章关联套票和茶饮两个 Event”的能力缺口尚未在本次实测。

### CVE-2024-3400

首阶段 Run 为 `failed`，后两个阶段为 `completed_with_errors`；最终有一个 Event、一条通知。首阶段 CVE3400-01 被模型指向不存在的 Event，状态提交报 `NOT_FOUND`；CVE3400-02 的 `proposed_state` / `update_kind` 至少有一个解析后为空。第二阶段重试时，CVE3400-01、02、03 也因同一条件报 `PROVIDER_SCHEMA`，无法仅凭报告确定各条具体缺少哪个字段。CVE3400-04 首次成功创建 Event，但时间已到 4 月 16 日，状态为 `new`，只记录了一条事实。CVE3400-05 的最终错误是模型服务请求失败。

最后阶段重新处理后，CVE3400-01、02、03 和 NVD 条目虽然被标为“处理完成”，模型却将它们判为 `confirmation`；状态管理器据此按 `no_change` 处理，没有写入披露、实际利用或修复进展。其中部分模型理由声称发现了新事实，与 `confirmation` 标签互相矛盾。NVD 材料的历史发布时间和版本未核实，不能据其判断当时的真实进展。

厂商公告 CVE3400-01、03、04 虽然共用 URL，本次回放中仍有各自的证据 ID、发布时间和内容哈希，**没有**被去重合并。上述失败发生在模型判断与状态提交阶段。

## 需要后续验证

1. 复核三个案例的证据摘要和 Ground Truth，完成 `draft` 裁定与冻结。之后按证据、Event、事实和里程碑分别评分；将未处理、模型服务失败与判断错误分开。对差异较大的证据先做人工逐条核查。
2. 已在模型输出校验与状态提交两层拒绝 `confirmation` / `no_change` 同时携带新事实或更新提案，相关定向测试已通过；仍需用相同设置重新试跑，确认模型能否在重试时改正。条件性字段为空、错误 `evidence_id`、不存在的 `event_id` 及本地模型服务间歇性失败尚需分别处理。修改后的全套回归测试尚未完成。
3. 支持一条 Evidence 分别关联多个 Event：当前 Orchestrator 对每条证据只调用一次 `provider.assess()`，Assessment 只有一个 `association` 和一份 `proposed_state`。MCD-03 一篇文章含截止时间不同的套票与茶饮优惠，目标是两个 Event 共用同一个 `evidence_id`，来源数仍为一。修复接口后再测试；修复前把缺失的第二个 Event 记为功能缺口。优惠到期驱动的状态更新也需要独立验证。
4. 核实 CVE 厂商公告各历史版本及 NVD 条目的来源时间。另设同 URL、正文高度相似但有实质更新的定向案例，检查近重复规则是否误合并；本次试跑没有发生这种合并。
